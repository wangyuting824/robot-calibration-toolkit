2　已有资料、原清单要求与六类交付

初始资料三份：机器人 URDF 建模资料确认清单.docx、robot_urdf_external_joints.zip、机器人总装（对外）.STEP。后补的数据统计表作为新的资料证据单独核对，不自动确认为实测参数；项目的 originals 和材料核对报告保留原件及来源。原始清单要求补齐“结构关系、轴线/零位、运行范围”。本会话另外约定独立运动学验证和 Isaac 动力学/接触对齐；这是扩展交付范围。

现有模型为 63 links / 62 joints（14 revolute、48 fixed）。双臂以外的头颈、腰腿、轮组和手指大多固定；±20°、0.5 rad/s、20 N·m 及质量惯性是测试默认值，不能作为真机参数。STEP 的 12 个顶层组件、62 个叶级实例、30 个候选组/30 条候选连接不等于实际自由度。

原清单涉及 C/A/B/W 分组、P000—P061 零件和 K 编号。A 为 STEP 负 X 侧/CAD L，B 为正 X 侧/CAD R；现场按实物和图纸确认，不能只按左右称呼。保留原零件名称、装配路径、型号、版本、日期及 STEP 一致性说明。原文提及的 STEP候选连杆与连接关系确认.xlsx 填回版尚未收到；新生成的结构对应表仅是替代记录，不能冒充原表。

原 DOCX 两张内嵌表仍为待填，未规定末端 mm/°、轨迹或动力学允许误差。configs/acceptance.yaml 的 null 需项目确认。希望越小越好不能替代一个可验收的阈值；指标应结合测量能力、姿态范围、负载、速度和工作空间约定。

3　官方依据是什么

这是依据官方接口、部件资料和公开算法实现的项目工具包；不是 NVIDIA 发布或认证的通用整机标定系统。官方文档规定模型/API、相机位姿求解、系统辨识和驱动行为。旭创整机的参考位置、范围、运动、力矩和负载试验规程由项目建立，结合适用部件资料与装配约束；不得直接照搬其它整机的动作流程。

  • NVIDIA：6.1 URDF Importer、SysID、Gain Tuner、PhysX/OpenUSD；见完整链接表 S06—S08、S20—S24。
  • OpenCV：相机内参、ChArUco 及 PnP，见 S01—S03。只提供算法依据，不能预先承诺实际毫米精度。
  • 设备厂家：角度编码器、事件锁存、动捕、六维跟踪、ATI 测力设备等；应按选定型号的安装/校准/采集手册操作。
  • 项目程序：SciPy 拟合、数据配对、RNEA、接触近似、应用与报告；来源及限制见 docs/sources.md、sources.yaml、third_party.md。ROS robot_calibration 是维护者发布的社区项目，不是旭创厂家的规程。

六维位姿测 XYZ 与方向；六维力/力矩测 Fx/Fy/Fz/Mx/My/Mz。两者不能替代。卡尺的 0.01 mm 显示分辨率也不等于测量准确度。

  1. 结构和轴线：核对原始结构表、CAD 和实物。只对确认可动关节标注轴上一点、单位方向、正向箭头、参考坐标和零姿态。原表数值为 mm/deg；程序表内用 m/rad。图纸无法满足精度时，选合适三维计量设备/服务，按其厂家规程安装和测量；软件不会从 STEP 自动发现真实轴线。
  2. 零位和反馈：由项目定义可复现的参考姿态和正方向，配参考工装或独立输出端角度/位移参考；使用现有控制程序或部件接口读取原始反馈。按项目确认的工况记录多个位置的 raw/reference，明确电机端/输出端、比例、减速关系和正方向。标定与验证另采，覆盖有效范围；不得用同一原始反馈生成 reference 自证。程序至少需要 3 个不同位置，实际采多少由覆盖和测量能力决定。
  3. 限位：依据结构干涉、线缆、部件行程与承载条件评估正常运行范围，建立项目检查规程。区分工作范围端点、软件边界、开关触发、已有机械边界记录；有开关时由驱动/采集接口记录触发瞬间位置，另记停止位置、方向与重复次数。没有开关则不虚构开关试验。本包只核验已采记录，不提供自动撞止挡/堵转/搜索极限程序。速度、加速度、额定/峰值力矩结合部件规格和装机条件确定，不以测得的最大行程直接代替工作范围。
  4. 相机路线：按 OpenCV 官方教程标定相机内参/畸变，测定板尺寸和安装关系，固定光学设置；将基座板与末端板刚性安装。采原始图像、两块板在相机坐标的位姿、识别质量和测量时间。先静态停稳采集；用独立尺寸/参考检验现场测量能力。相机重投影像素误差不是末端 mm 精度。
  5. 动捕路线：按 OptiTrack 等厂家手册标定相机空间，定义基座/末端刚体标记组，确认刚体原点和安装变换；导出位姿、时间、遮挡/跟踪质量。六维跟踪路线需配匹配六维靶标与参考坐标，普通单球靶不能给出完整方向。
  6. 质量惯性：核对每个真实刚体、附件和负载；可用校验过的秤核质量，用完整材料/BOM/CAD 质量属性或适用辨识方案取得质心/惯性。明确单位、参考点/轴，转到连杆质心惯性坐标。称重不能直接测出惯性，装机不可拆时不强制拆机。
  7. 驱动/动力学：按项目确认的试验计划记录实际输入、控制模式、q/dq/可信 ddq、力矩语义、前馈/饱和/负载和时间。电流不是自动可信的输出端关节力矩；末端六维力也不能直接给全部关节驱动力矩。优先按 NVIDIA SysID 适用流程或已有真实记录选择可辨识参数。
  8. 接触：按实际材料、表面和负载设计试验，用适用测力装置配位移/滑速测量；法向、切向、滑动和冲击各采匹配观测。ATI 等设备先按手册安装、去皮/校验、定义坐标。滑动数据不能辨识静摩擦，线性柔顺结果不能直接当 PhysX 任意参数。
  9. 同步：保留设备的测量时间与电脑接收时间，说明触发/PTP/共同时钟或独立测得的时钟关系。采样行号不能当时间；不能把曲线任意平移来美化误差。停稳采集可降低动态同步误差，动态试验仍需实际同步依据。

Excel 里向量写空格分隔，如 0 0 1。程序主表统一 m/rad/kg/s/N/N·m，四元数 qx qy qz qw；URDF 的 RPY 是固定轴 XYZ。mm 除以 1000，deg 乘 π/180。惯性为 kg·m²，顺序 ixx iyy izz ixy ixz iyz；必须是关于质心、指定惯性轴的张量，不能直接复制关于 CAD 世界原点的量或混用积惯量符号。

robot_parameters.xlsx 的 9 张表：robot_info 填型号/版本及单位；links 填名称、质量、COM、惯性、来源和确认状态；joints 填父子、类型、origin/axis、范围/速度/力矩、阻尼/摩擦和 mimic；geometry 填几何来源与安装变换；frames 记录基座/工具坐标；actuators 记录反馈与控制定义；mechanisms 记录联动/闭环；contacts 记录接触定义；sources 记录图纸、文件、修订和链接。各表完整列名见附录，缺项保留空白/unconfirmed，确认后填 confirmed 和真实来源。frames/actuators 的记录不会自动写入实机控制器。

初始主表从测试 URDF 重建，所有参数保持 unconfirmed。不要批量改 confirmed。头颈、腰腿、轮组、夹爪真实自由度、闭环及非线性联动需要先改结构；线性 mimic 只能描述实际线性联动。每个闭环要提供工程确认的约束实现，不能靠空列表认定无闭环。

configs/calibration.yaml：observed_frame 为测量坐标名；tip_link 为要验证的模型末端；base_xyz_rpy = T_测量坐标_模型根；tool_xyz_rpy = T_模型末端_被测对象。先填已测安装关系，再按可观测性选择 free_parameters。每项 kind 是 joint_offset/base/tool/joint_origin；关节填 joint，坐标分量填 component，lower/upper 是允许修正范围且包含 0；position_sigma_m/angle_sigma_rad 用测量能力依据填写，不能为了降残差任意改权重。

例如只释放一个关节零偏的配置形状如下。这只是字段形状，数值需按本机依据填写，不能原样当旭创参数：

  - kind: joint_offset
    joint: 实际关节名
    lower: 允许最小修正_rad或m
    upper: 允许最大修正_rad或m

configs/limits.yaml：joints.关节名 下填 lower/upper（rad 或 m）、kind（software_boundary/switch_latch/operating_range_check/manufacturer_stop_record）、source、tolerance、repeatability_peak_to_peak、minimum_repeats。自研整机的 operating_range_check 对应已评估的工作范围端点检查，不证明机械极限。URDF 的 lower/upper 填项目确认的正常运行范围。写“360°”不能自动认定为 continuous，需确认线缆、滑环与运行方式。

configs/interfaces.yaml：operating_procedure 填项目试验规程文件及版本，procedure_owner 填责任方，commissioning_reference 记录接口调试依据；仍须确认 limits_confirmed、起点容差、stop/watchdog 等能力。旧 manufacturer_procedure 可兼容，拼装整机无需填写该旧字段。

configs/acceptance.yaml：kinematics.max_position_m / max_orientation_rad 是真机位姿误差；asset 的六项是导入一致性容差；runtime_kinematics.max_position_m / max_orientation_rad 是仿真软件一致性容差，需自行增加并声明；dynamics.required_metrics 与 max_abs 声明 q/dq/tau/normal_force/slip_velocity 的验收范围。每种容差有不同用途。

configs/jobs.yaml：统一入口使用的实际程序参数。reference-fit.options.f_scale 用参考测量单位填写稳健拟合尺度；所有路径相对项目目录。R01 是一组固定模型/配置/数据版本；更改参数或输入后用 R02，并将模型哈希、数据版本等一并更新重新验证。若只做后续一步且仍引用旧模型，应明确修改 job 的输入路径，不能借新版本名掩盖旧模型。

6　采集、坐标变换与时间配对

可直接走现有控制程序/设备软件导出路线：机器人调试软件导出关节记录，测量仪器软件导出位姿/力数据；原始文件保存 data/raw；按上表列名生成 CSV 和来源 YAML。这条路线不依赖 Codex，也不要求设备一定有 Python SDK。自动在线采集需要在 adapters/ 中实现并验证该型号的 SDK；robot_adapter_template.py 和 metrology_adapter_template.py 只是接口模板，尚不是旭创驱动。ROS 只读、OpenArm 和 replay 成功不能替代旭创设备验收。

两块靶标都在同一测量坐标 M、相同时钟下：B 为机器人基座，Bm 为基座靶，E 为被测工具，Em 为末端靶。按工装测得 T_B_Bm、T_E_Em，仪器测 T_M_Bm、T_M_Em，则：

T_B_E = T_B_Bm × inverse(T_M_Bm) × T_M_Em × inverse(T_E_Em)

程序 transform-poses 实现此式。填写 configs/pose_transform.yaml：两份靶标 CSV/manifest、两项安装变换（xyz/rpy，m/rad）、installation_reference、input_length_unit、maximum_time_difference_s、required_quality 和 observed_frame。必须有同步的测量时间和合格质量。输出 poses.csv 为基座中工具的独立位姿，m、xyzw；它不会使用 URDF 生成真值。若设备直接输出所需坐标下的工具位姿，可跳过此步。所有变换都代表“子坐标在父坐标中的位姿”，不是反过来。

bash 启动工具包.sh transform-poses --project projects/旭创现场项目

然后填写 configs/pairing.yaml：feedback/poses 及对应 manifest、dataset_id、role、observed_frame、maximum_time_difference_s、pose_time_offset_s、time_sync_reference、三种输入单位和 required_quality。若更改过真实自由度，增加 urdf 指向该版本名义模型。两个时间轴的已知关系是“pose时间 + pose_time_offset_s = 反馈时钟”；偏移量来自独立同步依据，不从误差曲线反推。原始时间统一秒。

bash 启动工具包.sh pair-poses --project projects/旭创现场项目

pair-poses 按时间最近的完整关节帧配对，不插值、不自动删除坏点、不补缺关节、不裁限位。同一反馈帧重复用于不同位姿、任何关节时间超差、四元数不规范或质量失败均会拒绝。输出宽表、同名 manifest 和 pairing_audit.csv。验证集另采、换输出文件名、dataset_id 和 role，再单独配对。静态采集仍需记录停稳和测量时间，程序不自动判定本项目允许的运动状态。

若测量姿态仍是板而不是工具，calibration.yaml 的 tool_xyz_rpy 应为模型末端到板；若已换算到工具，则填模型末端到工具。不能在测量侧变换一次后，又在 tool_xyz_rpy 重复施加同一安装变换。

9　Isaac与MuJoCo怎么运行，动力学怎么复验

改动后的复验顺序：先保存旧参数/模型/报告 → 改主表及来源 → 新版本结构检查和名义模型 → 若坐标/结构影响旧标定，重测或重拟合并留出验证 → apply / verify-applied → 重导Isaac与静态检查 → 同工况动态/接触留出验证 → 报告与分类/完整备份。
